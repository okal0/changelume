# Architecture and trust boundaries

`packages/core` contains Zod configuration/state validation, models, source collection, language adapters, recipe planning, isolated candidate generation, verification, LLM adapter, and Octokit publishing. `packages/cli` is a Commander adapter. Stripe has selected migrations in TypeScript/JavaScript/Python and one conservative lexical migration per Go, Java, C#, PHP and Ruby. The latter five are not compiler-semantic analyzers. There is no Rust component or persistent service.

The TypeScript compiler's binding information, accessed through ts-morph, traces default import symbols and local client declarations. Shadowed identifiers and unrelated objects do not match. Discovery uses an isolated project with no dependency resolution or project-script execution. If SDK packages are absent, reports explain that SDK type checking is unavailable. Edits use ts-morph text ranges and preserve unrelated source exactly.

Source collection always includes a bundled, unmodified official v12 changelog snapshot with a computed SHA-256. Online mode additionally fetches the official master changelog, limits response bytes, times out requests, retries at most the configured count, and caches validated content for one hour. A changed upstream format is an error. There is no stale-cache fallback on network failure: use `--offline` deliberately. The cache is disposable.

Release headings are observations, not understood changes. Each automatic edit has a stable recipe ID, version floor, language-specific lexical precondition, source-to-target change and direct official changelog URL. The five native-language rules are deliberately narrow and are not general compiler-aware migrations. Every other observed release remains unclassified. `newlyObserved` compares against disposable observation history under `.changelume/observations/`, separately for offline and online sources. Unclassified changes remain visible after observation. Scans never advance accepted migration state.

Plans bind source evidence, version applicability, locations, file hashes, a stable recipe ID, and Git revision. Reports omit full edited-file contents; candidate artifacts necessarily contain the selected source. The baseline accepts only the recipe and its historical source hash; it never marks all observed releases understood.

Candidate generation clones the local committed repository into a new temporary directory, applies allowed edits, generates a patch, and optionally runs configured commands with a minimal environment. Git hooks and external diff/textconv are disabled. Source file bytes and overall edit sizes are bounded. Failed checks retain artifacts, and unexpected tracked mutations during local verification fail the candidate. The temporary checkout is removed afterward. Normal application rechecks revision, dirty state, and every file hash. Application stages originals and candidate files in a recovery directory before replacing source. An interrupted replacement triggers rollback; the recovery manifest and copies remain on failure. A hard process termination can still require manual recovery using that manifest.

LLM context is opt-in, hash-confirmed, and limited to affected files. The provider can return data only. The MVP validates output against the deterministic recipe as an additional semantic boundary. Credential heuristics cannot identify arbitrary sensitive strings: preview remains essential.

GitHub publication creates a tree and commit through the API; it does not run customer code or push a checked-out worktree. Branch identity includes recipe ID and analyzed commit. Existing PRs are returned unchanged. If PR creation failed after branch creation, publication can retry only when the branch commit message, single parent, and complete tree match the expected generated commit. Human changes require manual inspection. A moved base branch requires reanalysis. Unit tests mock publication; live private-consumer validation is recorded in the validation document.

Constructor bindings used outside supported direct constructors are conservatively declined, including mutations and escapes. Credential checks inspect literal arguments to imported Stripe constructors, while ordinary Date/Error string constructors are permitted. Verification captures at most 64 KiB per stream and preserves at most 16 KiB per stream in JSON and Markdown reports. Output is marked truncated when bounded; ANSI escapes, recognized credential patterns, and known secret environment values are redacted. Arbitrary sensitive output cannot be recognized comprehensively.
