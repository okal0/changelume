# Private beta protocol

The release candidate is 0.2.0-rc.1. Build with `pnpm build`, then set `CHANGELUME_NPM_CLI` to npm's JavaScript entry point and run `node scripts/package.mjs`. The archive, checksums, standalone Action, notices, and documentation are staged under `.demo/release-candidate`. Install locally with `npm install --global /absolute/path/to/changelume-0.2.0-rc.1.tgz`. The archive has no runtime dependency-install scripts. Node 24 and Git are required.

Start in a committed customer repository: run `changelume init`, configure verification, commit configuration, then run `changelume doctor --offline`, `changelume scan --offline`, `changelume review --offline`, and `changelume migrate --offline --dry-run`. Reports remain under `.changelume`. `review --acknowledge ID --note TEXT` records review in `changelume.review.json`; commit this file separately. An upstream evidence change invalidates acknowledgement. Acknowledgement never changes the accepted migration baseline or hides unresolved changes.

Private beta acceptance uses six controlled repositories: ESM affected constructors, unaffected CommonJS/direct constructors, legacy request options, mutated bindings, ambiguous options, and named imports. `node scripts/beta.mjs` records expected/proposed files, unsupported findings, dry-run preservation, applied-source correctness, configured verification, and second-plan idempotence. The same evaluation runs against the independently installed archive. Synthetic repositories are automated evaluations, not feedback from external developers. The user selected controlled fixtures for this iteration. Independent maintainer trials and usability feedback remain an explicit release gate; no fabricated participants or adoption metrics are claimed.

Supported additional rules rename inline `customers.create(params, options)` keys: api_key→apiKey, idempotency_key→idempotencyKey, stripe_account→stripeAccount, stripe_version/stripeVersion→apiVersion. They require a const local Stripe client, literal property assignments without spreads/computed keys/collisions, supported root SDK 10/11/12, and no escaped client bindings. Other operations and options passed through variables require manual review. These rules implement the official Stripe 11 removal of deprecated request option names. Simple exported const clients and single-return exported factories can be traced across relative imports for inventory; cross-file edits and arbitrary factories remain unsupported. Any source-file constructor mutation/escape conservatively blocks automated edits across the repository.

Filter review items using `review --offline --pending --category 'manual review'`. JSON output includes source URLs, hashes, SDK evidence, and repository locations. Acknowledgement becomes stale if relevant repository or upstream evidence changes.

Release maintenance: update only through reviewed source/lockfile changes, rebuild bundles, run tests and real-SDK fixtures on Linux/Windows, and preserve CLI/Action compatibility evidence. Treat unknown upstream formats as errors. Security fixes should include regression coverage and a documented affected version range. A public release requires human beta feedback and explicit publication authorization.
